# Model interpretation and direct application execution

Gemini interprets natural language once into a typed `TurnPlan`. Python validates and executes the contract directly. There is no regex/keyword language parser, mandatory second-model plan reviewer, or model loop choosing the queries a second time.

## Workflow and shared capabilities

1. Validate input length and apply the existing defense-in-depth check for recognizable pasted personal data.
2. Supply the current question, up to four prior turns, prior analytical contract, trusted startup identity, UTC date and executable capability manifest to the planner. It has no tools. The provider schema requires every analytical decision and filter to be explicit; omitted analytical fields are rejected rather than inheriting defaults.
3. `capabilities.py` derives query fields, supported output enums and numeric bounds from the same Pydantic schemas used by the application. It supplements these with metric, privacy and time-boundary semantics. Unsupported-filter/metric and out-of-range responses carry typed issues checked against those schemas. Monthly cardinality is explicitly described as one row per intersected calendar month; out-of-range issues reference the executable numeric property (limit) rather than inventing a separate months field. Application text explains the requested constraint without silently replacing it. Clarification must identify missing information; this is a structural check, not proof that the information really is missing.
4. Validate the complete contract, permissions and query count before any query. A malformed or incompatible plan gets at most one repair with sanitized validation feedback, under the original budget. Authorization denial is never repaired by broadening scope. Resource/provider failures do not become semantic repair loops.
5. `execution_requests` expands requirements into exact typed requests. Totals/monthly measures share a query; separate ranked measures retain separate queries. Monthly limits cover all intersected months. Scope, status rules, IDs and inactivity thresholds come directly from the validated contract. Empty results do not trigger exploratory queries or removal of filters.
6. Execute through the existing compiler and BigQuery gateway. Code selects requested facts and computes ratios/comparisons. The primary period is evaluated relative to the explicit comparison baseline, regardless of chronological order or gaps. Compatible filters, scope and definitions are required; a zero baseline produces an undefined percentage, not invented growth. For an empty sales aggregate, zero units/orders/customers establish zero revenue despite SQL SUM returning NULL; missing revenue on a nonempty population remains unknown. Raw evidence is preserved. Simple tables and churn snapshots need no further model call. Effective query scope and explicit product/customer filters are visible, including empty results.
7. Requested actions use one ADK `LlmAgent` over already verified evidence, with no analytical or library tools. Native structured output returns metric references, hypotheses and proposed actions. Numeric/action/completeness checks remain mandatory, with at most one tool-free narrative repair and a verified-figures fallback. Explicitly requested interpretation can add separately reviewed optional commentary; ordinary rankings no longer trigger commentary automatically.

Planning, repair, queries, narration and commentary share the same cost/call/deadline budget and pacer. No budget reset or unlimited loop was introduced. The provider wrapper permits one retry for transient API or HTTP transport failures, including read timeouts; the SDK is configured for one attempt to prevent nested retries. Exhausted transport failures have a specific timeout/connection message; exhausted API 504 and other transient server errors also receive status-specific availability messages. This is resilience, not an availability guarantee. The schema normalization callback converts ADK's native output model class to JSON Schema before serialization and accounting; this was checked against locked ADK 2.12.

## Library operations and authority

Natural-language library operations use typed routes and owner-scoped application services. A bounded list of up to four typed library operations supports compound requests in order, including cancellation. Known read IDs and save availability are preflighted before mutations; completed steps are not rolled back when a later operation fails. A dedicated help route explains operation semantics without executing them. Analytical and library mutations cannot be combined in one plan; the planner must request separate turns instead of silently dropping a task. Creating a report never saves it implicitly; an explicit later save can persist the last successful analysis. Exact report reads use stored data. Deletion only prepares a preview: no model route can confirm it, and only `/confirm TOKEN` can hard-delete the exact previewed set. Deterministic slash commands remain available without the model.

Identity is never a model-controlled field. Python still owns permissions, SQL compilation, cohort suppression, result contracts, arithmetic, resource limits and deletion confirmation. Technical regexes remain for PII redaction, format escaping and reference tokens; none interprets the user's analytical intent. Stored contracts from earlier versions remain readable through data migration.

## Correctness and verification

Schema validity is not semantic correctness. Removing the blanket reviewer eliminates its observed false rejections and overhead, but an incorrect schema-valid interpretation can still execute within authorized capabilities. We make no claim that a deterministic validator understands the original question. Semantic regressions and fresh held-out live tests remain necessary, alongside independent numerical SQL checks.

Offline tests exercise real planning/repair orchestration, direct synthetic SQL execution, preflight rejection, shared budgets, filter retention, completeness, ADK narration without query tools, and report state. Explicit recorded contracts isolate renderer/executor tests; they are not a test-only natural-language parser. Obsolete tool-selection-loop and blanket-review assertions were replaced rather than reported as retained coverage.

The same 20 cases from the fresh corner audit are rerun after the migration, preserving original questions, identities, session dependencies and runtime settings. They are now regressions, not a fresh holdout. Raw first-attempt traces, independent oracle queries and state checks are retained locally. Results are linked in the [evaluation record](evaluation.md).

Output remains primarily English even when the planner understands a Polish request. Supported analytics still require compiler capabilities; free-form SQL is not an escape hatch. Explicitly requested commentary is fallible and can be withheld without removing verified facts.

## Official research sources

- [Gemini structured outputs](https://ai.google.dev/gemini-api/docs/structured-output): typed output schemas need application-side validation; they do not prove semantic truth.
- [Gemini function calling](https://ai.google.dev/gemini-api/docs/function-calling): model proposals and application execution have separate authority.
- [ADK LLM agents](https://adk.dev/agents/llm-agents/) and [ADK safety](https://github.com/google/adk-docs/blob/main/docs/safety/index.md): explicit boundaries, output schemas and application policies. The optional report agent cannot query or mutate reports.
- [Google's ADK skills guide](https://developers.googleblog.com/en/developers-guide-to-building-adk-agents-with-skills/): progressively loaded skills were considered; this fixed analytical surface does not need dynamic skill installation.
- [Building effective agents](https://www.anthropic.com/research/building-effective-agents): use composable workflows and add model decisions where needed. The direct workflow avoids repeating a decision already captured by a validated contract.
